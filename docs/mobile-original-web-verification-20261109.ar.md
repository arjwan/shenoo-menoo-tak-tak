# فحص ربط تطبيقات الهاتف بتطبيقات الويب الأصلية
التاريخ: 9 نوفمبر 2026

## النتيجة
أُصلحت طبقة الاتصال والاختلافات المثبتة بين الهاتف وخدمات الويب الحالية. شنو منو واتصال يستخدمان حسابات وجلسات وبيانات shinomino.com نفسها. تطبيق الموظف يتصل بخادم pro.alarjwan-softwear.com وبمعرّف الجهاز المرتبط بالموظف.

هذا التقرير يميز بين الاختبار الآلي، والتحقق الحي دون حساب، والاختبار الذي يحتاج هاتفاً وحساباً فعليين. لم تُستخدم بيانات مستخدمين حقيقية في الاختبارات المعزولة، ولم تُسجّل بصمة حضور أو طلب موظف في الإنتاج.

## الإصلاحات المثبتة
- استبدال انتظار Bearer Token بجلسة Cookie المطابقة لخادم الويب، والتحقق عبر /api/auth/session قبل دخول الواجهة.
- إلغاء الجلسة من الخادم عند الخروج، والعودة إلى الدخول عند انتهاء الجلسة.
- تقييد طلبات الجلسة بنطاق الخدمة الأصلية، وإيقاف تحويل الطلبات آلياً إلى نطاق آخر.
- إضافة type: text إلى إرسال الرسالة، واستعمال DELETE لإلغاء الإعجاب.
- تحديث المحادثات وإيصالات القراءة مع إيقاف التحديث الدوري عند تعليق التطبيق.
- تصحيح فهرس سومر إلى items وفق الاستجابة الحية، وإتاحة فتح مصدر الكتاب الأصلي.
- رفع الملفات بأجزاء وفق خدمة /api/uploads الأصلية، حتى 100 ميغابايت، وإلغاء الرفع غير المكتمل عند الفشل.
- إيقاف النشر إذا أُغلقت صفحة الإنشاء أثناء الرفع.
- ربط الحضور بمراجعة اشتراط البصمة، وGPS حديث ودقيق، وتحدي الخادم، والتحقق الحيوي في Android.
- منع إرسال حضور متأخر إذا أُغلقت عملية التحقق.
- ربط طلب الانضمام بخدمة /api/employee/request مع انتظار اعتماد إدارة الشركة.

## التحقق الحي دون حساب
| الطلب | النتيجة |
|---|---|
| GET https://shinomino.com/api/health | 200؛ الخدمة الأصلية d1+r2 |
| GET https://shinomino.com/api/auth/registration-config | 200 |
| POST https://shinomino.com/api/auth/signin ببيانات فارغة | 400؛ رفض صحيح |
| GET https://shinomino.com/api/auth/session دون جلسة | 401؛ رفض صحيح |
| GET https://shinomino.com/api/school/curriculum/catalog | 200؛ الحقول items وtotal |
| POST https://pro.alarjwan-softwear.com/api/mobile/login ببيانات فارغة | 400؛ رفض صحيح |
| GET إشعارات المراقب دون معرّفات | 500 من الخادم بدلاً من رفض تحقق واضح؛ ملاحظة باقية في الخدمة الأصلية |

لم يُختبر دخول ناجح بحساب إنتاجي، أو تبادل رسائل على الإنتاج، أو GPS وبصمة وكاميرا وميكروفون على جهاز فعلي. لا يعني نجاح الاختبارات المعزولة ثبوت هذه الحالات.

## تشغيل الاختبارات
- اختبارات Flutter: flutter analyze ثم flutter test ضمن كل مشروع.
- اختبار Worker الأصلي على SQLite معزولة: node --test tests/native-web-integration.test.mjs
- يحاكي اختبار التخزين عمليات R2 في الذاكرة؛ لا يقيس اتصال R2 الإنتاجي أو فك ترميز فيديو فعلي.
- ملفات Android الناتجة من مسار العمل الحالي هي Debug للاختبار؛ توقيع Release التجاري وبناء iOS لم يُنجزا.
