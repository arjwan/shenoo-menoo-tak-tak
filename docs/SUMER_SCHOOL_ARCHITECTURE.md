## 1. الهيكل العام للتطبيق الموحد (Unified Single Application Shell)

### 1.1 الرؤية والهدف الأساسي
بناء تطبيق ويب موحد وشامل لمدرسة سومر الأهلية الإلكترونية (`Sumer School Unified Single Application Shell`) يعتمد على مدخل تشغيلي واحد في المستقبل هو `school.html`، دون إعادة إنشاء واجهات الـ 12 صفحة القديمة (`Legacy UI Pages`) بأسماء أخرى أو قوالب مكررة، وبحيث تدار كافة واجهات الطلاب والمعلمين وأولياء الأمور والإدارة عبر صدفة برمجية مركزية واحدة (`Single-Page Shell`).

### 1.2 المبادئ التوجيهية الصارمة (Architecture Core Rules)
1. **الصدق والنزاهة في البيانات (No Fake Data):**
   - حظر إنشاء أي بيانات تجريبية أو وهمية (طلاب، معلمون، علامات خيالية).
   - الارتباط الحصري بالمناهج العراقية الرسمية المعتمدة (108 كتب، 136 ملف PDF، و 17,232 صفحة مفهرسة بنصوص الـ OCR).
2. **الخصوصية والأمان الافتراضي (Privacy by Default & Zero Surveillance):**
   - الكاميرا والمايكروفون مغلقان إجبارياً وافتراضياً عند دخول الحصص.
   - حظر أي تقنيات للمراقبة الخفية أو تسجيل الصوت/الفيديو (`MediaRecorder` و `FaceDetector` محظوران تماماً).
   - الموافقات السبع لأولياء الأمور (`Guardian Consents`) اختيارية صريحة حصراً (`Opt-in only`, default false)، وتخضع لتدقيق كامل ولا يملك المعلم صلاحية تجاوزها.
3. **الأرشفة والتعطيل بدلاً من الحذف الإتلافي:**
   - حظر الحذف الفيزيائي للطلاب أو المعلمين أو السجلات؛ يتم الاعتماد على الأرشفة مع توثيق السبب في `AuditLog`.
4. **فصل صلاحيات المنصة عن إدارة المدرسة:**
   - مدير المدرسة (`manager`) يدير الشؤون المدرسية فقط.
   - رتب المنصة (`admin` / `developer`) محكومة بآلية أمان خادمية مستقلة، ولا ينشئ التطبيق أي مساحة باسم "Developer Super-Admin Workspace" داخل المدرسة.

## 2. التكامل مع حساب شنو منو (Shno Meno Authentication & Context Flow)

لا تمتلك مدرسة سومر نظام مصادقة منفصل، بل هي جزء عضوي من شبكة **شنو منو**. يتم استخدام نظام الجلسات والمصادقة المركزي لمنصة شنو منو:

```
+-----------------------------------------------------------------------------------+
|                        Authentication & School Context Flow                       |
+-----------------------------------------------------------------------------------+
                                          |
                                          v
                         +----------------------------------+
                         |  POST /api/auth/signin           |
                         |  (Username/Phone + Password)     |
                         |  JWT Token returned              |
                         +----------------------------------+
                                          |
                                          v
                         +----------------------------------+
                         |  GET /api/school/management/me   |
                         |  (Bearer Token in Header)        |
                         +----------------------------------+
                                          |
         +--------------------------------+--------------------------------+
         |                                |                                |
         v                                v                                v
+------------------+             +------------------+             +------------------+
| User Role:       |             | School Context:  |             | Active Entities: |
| - user           |             | - isTeacher      |             | - Teacher doc    |
| - moderator      |             | - isGuardian     |             | - Guardian doc   |
| - admin          |             | - isStudent      |             | - Student doc(s) |
| - developer      |             | - isManager      |             | - Children array |
+------------------+             +------------------+             +------------------+
         |                                |                                |
         +--------------------------------+--------------------------------+
                                          |
                                          v
+-----------------------------------------------------------------------------------+
|                        Workspace Routing & Client Context                         |
|                                                                                   |
|  - If role == guest / user without profile -> #welcome / #guest                   |
|  - If isStudent == true                    -> #student/overview                   |
|  - If isTeacher == true                    -> #teacher/overview                   |
|  - If isGuardian == true                   -> #guardian/overview                  |
|  - If isManager || isDeveloper == true     -> #admin/overview                     |
+-----------------------------------------------------------------------------------+
```

## 3. مساحات العمل المستقلة (Independent Workspaces)

تم تصميم 4 مساحات عمل مدرسية رئيسية معزولة تماماً في الواجهة، بالإضافة إلى بوابة الزوار العامة:

### 3.1 بوابة الزوار والتسجيل (Public / Guest Gateway)
- **المسارات:** `#welcome`، `#guest`، `#auth/login`، `#auth/register-student`، `#auth/apply-teacher`.
- **الوظيفة:** استعراض المدرسة، الهوية السومرية، استعراض عناوين المناهج العراقية، تسجيل الطلاب الجدد، وتقديم طلبات انضمام المعلمين.

### 3.2 مساحة عمل الطالب (Student Workspace)
- **المسارات:**
  - `#student/overview`: لوحة المؤشرات، الحصص القادمة، والواجبات المستحقة.
  - `#student/classes`: الحصص المباشرة والافتراضية الجارية والمجدولة.
  - `#student/schedule`: جدول الحصص والاختبارات الأسبوعي.
  - `#student/assignments`: استلام وحل الواجبات ومتابعة درجاتها.
  - `#student/grades`: كشف الدرجات ومعدل المواد ودفتر العلامات.
  - `#student/attendance`: سجل الحضور والغياب الذاتي ونسب الالتزام.
  - `#student/progress`: مسار تقدم الطالب في المناهج والدروس المنجزة.
  - `#student/teachers`: قائمة معلمي الطالب (الحقيقيون والافتراضيون).

### 3.3 مساحة عمل المعلم (Teacher Workspace)
- **المسارات:**
  - `#teacher/overview`: لوحة المعلم اليومية، والتنبيهات، وحصص اليوم.
  - `#teacher/classes`: الفصول والشعب والمواد المكلف بها وإطلاق الحصص.
  - `#teacher/students`: قائمة الطلاب المكلفين بالمعلم وتفاصيلهم.
  - `#teacher/schedule`: جدول الحصص الأسبوعي وجدولة مواعيد الاختبارات.
  - `#teacher/attendance`: رصد حضور وغياب الطلاب في الحصص الحية والمجدولة.
  - `#teacher/assignments`: إنشاء الواجبات ومراجعة حلول الطلاب ورصد العلامات.
  - `#teacher/gradebook`: دفتر درجات الطلاب وتقييمات الفترات والاختبارات.
  - `#teacher/reports`: تقارير أداء الطلاب وملاحظات المتابعة الأكاديمية.
  - `#teacher/messages`: التواصل المباشر مع أولياء الأمور وإدارة المدرسة.

### 3.4 مساحة عمل ولي الأمر المستقلة (Guardian Workspace)
مساحة عمل مستقلة تماماً ومنفصلة عن دور الطالب، وتشمل:
- **المسارات:**
  - `#guardian/overview`: اللوحة المركزية لولي الأمر، ملخص الأبناء، والتنبيهات العاجلة.
  - `#guardian/children`: إدارة ملفات الأبناء واختيار الابن النشط (`Active Child Switcher`).
  - `#guardian/schedule`: الجدول الدراسي الموحد لجميع الأبناء مع تصنيف المواعيد.
  - `#guardian/grades`: كشوفات درجات الأبناء والتقييمات التفصيلية لكل مادة.
  - `#guardian/attendance`: سجلات حضور وغياب الأبناء وإشعارات التأخير.
  - `#guardian/reports`: التقارير الأكاديمية الدورية وشهادات التقدم لكل ابن.
  - `#guardian/teachers`: قائمة المعلمين المشرفين على تدريس الأبناء.
  - `#guardian/messages`: قنوات التواصل المباشرة مع المعلمين وإدارة المدرسة.
  - `#guardian/consents`: إدارة وتحديث الموافقات السبع الصريحة لكل ابن.
  - `#guardian/complaints`: رفع الشكاوى والمقترحات للإدارة ومتابعة الردود الرسمية.
- **قيد الخصوصية والأمان الصارم:** **لا يُسمح لولي الأمر بالتصرف كطالب داخل الحصة**، ودخوله الحصة مقيد بصفة مراقب وفق ما يفرضه الخادم حصراً.

### 3.5 مساحة عمل الإدارة المدرسية الموحدة (School Administration Workspace)
- **المسارات:**
  - `#admin/overview`: المؤشرات الإدارية الشاملة وأعداد المستخدمين وحالة الحصص.
  - `#admin/teachers`: إدارة المعلمين، طلبات الانضمام، وتعيين المواد والصفوف.
  - `#admin/students`: إدارة الطلاب، السجلات الأكاديمية، وحالة النشاط/الأرشفة.
  - `#admin/guardians`: إدارة أولياء الأمور وحالة الموافقات القانونية.
  - `#admin/classes`: إدارة المراحل والصفوف والشعب الدراسية والمناهج.
  - `#admin/schedules`: إدارة الجدول الدراسي العام والمواعيد الموحدة للامتحانات.
  - `#admin/attendance`: تقارير الحضور والغياب الشاملة على مستوى المدرسة.
  - `#admin/gradebook`: المراجعة العامة للدرجات والسجلات الأكاديمية الدائمة.
  - `#admin/complaints`: صندوق شكاوى أولياء الأمور، الرد الرسمي، وتغيير الحالات.
  - `#admin/audit`: سجل التدقيق الإداري الصارم لجميع العمليات مع التوقيت وهوية الفاعل.
- **فصل صلاحيات المنصة:** مدير المدرسة (`manager`) يدير شؤون المدرسة ولا يملك صلاحية تغيير رتب الحسابات إلى مطور أو التلاعب بأمان المنصة (`admin` / `developer`).

## 4. تدفق التسجيل وفترة التجربة المجانية (Onboarding & 30-Day Trial)

1. **تسجيل الطالب وربطه بولي الأمر:**
   - يسجل ولي الأمر حساباً على منصة شنو منو، ثم يضيف أبناءه محدداً المرحلة والصف والشعبة والمواد.
   - يرتبط الطالب تلقائياً بـ `User` ولي الأمر، ويمنح الطالب فترة **تجربة مجانية مدتها 30 يوماً** (`Free Trial = 30 days`).
2. **طلب انضمام المعلم (Teacher Application):**
   - **الزائر العادي لا يستطيع إنشاء حساب معلم فعال مباشرة بمجرد التسجيل.**
   - يتقدم الراغب بالتدريس بطلب انضمام (`Teacher Application`) يتضمن تخصصه وسيرته الذاتية ومراحله المفضلة.
   - يظل الطلب بحالة معلقة (`pending`) حتى تراجعه إدارة المدرسة في مساحة الإدارة، وتعتمد الحساب الحقيقي وتحوله إلى `SchoolTeacher` نشط.

## 7. معمارية الصف الموحد (Unified Classroom Architecture)

تدمج نواة الصف الموحد (`SumerClassroomCore`) بين التعليم الحي والتفاعلي:
- **الأنماط:** حصة حية مع معلم حقيقي (`WebRTC Star Mesh`) أو حصة ذكية مع معلم افتراضي (`AI Persona`).
- **المكونات الأساسية داخل الصف:**
  - مسرح الفيديو / المعلم الافتراضي.
  - السبورة التفاعلية الذكية متعددة الأدوات والشرائح (تكبير 50%-200%، تراجع/إعادة).
  - قائمة الحضور الحقيقية ورفع اليد وإدارة الأذونات.
  - الدردشة المباشرة النصية داخل الحصة.
  - ضوابط الأجهزة الصارمة: **الكاميرا والمايكروفون مغلقان دائماً وافتراضياً عند الدخول**، ويخضعان لموافقة ولي الأمر الصريحة.

## 8. المنظومة المشتركة: الحضور والتقدم والتقارير (Shared Subsystems)

بناء المكونات الثلاثة كمنظومة برمجية مشتركة (`Shared Logic`) مع تباين العرض حسب الدور:
1. **الحضور والغياب (`Attendance`):**
   - *الطالب:* سجل الحضور والغياب ونسب الالتزام.
   - *المعلم:* رصد الحضور بنقرة واحدة أثناء الحصة، وتعديل السجلات السابقة.
   - *ولي الأمر:* إشعارات فورية عند تسجيل غياب أو تأخير للابن النشط.
   - *الإدارة:* تقارير إحصائية شاملة ومعدلات الغياب على مستوى المدرسة.
2. **التقدم والإنجاز (`Progress`):**
   - *الطالب:* مسار إنجاز المنهج، حل الواجبات، ونقاط التفاعل.
   - *المعلم:* نسب إنجاز الخطة الدراسية للفصول واستيعاب الطلاب.
   - *ولي الأمر:* شريط تقدم الابن النشط في مواده ومعدله التراكمي.
   - *الإدارة:* مؤشرات الأداء العام للمراحل الدراسية ونسب إكمال المقررات.
3. **التقارير الأكاديمية والسجلات الدائمة (`Reports`):**
   - *الطالب:* كشف الدرجات الفصلي والبطاقة المدرسية.
   - *المعلم:* تصدير كشوف العلامات التفصيلية والملاحظات التربوية.
   - *ولي الأمر:* استخراج الشهادات الدورية والبطاقة المدرسية لكل ابن.
   - *الإدارة:* السجلات الدائمة والأرشفة وتصدير بيانات وزارة التربية.

## 10. معمارية الإشعارات والمراسلات المدرسية (Notifications & Messaging)

1. **الإشعارات المدرسية:**
   - إشعارات بدء الحصص المباشرة والتذكير قبلها بـ 15 دقيقة.
   - إشعارات نشر الواجبات واقتراب مواعيد تسليمها ومواعيد الامتحانات.
   - تنبيهات فورية لولي الأمر عند تسجيل غياب أو رصد درجة جديدة.
   - تعاميم وتوجيهات إدارة المدرسة الموجهة للطلاب أو المعلمين أو أولياء الأمور.
2. **المراسلات المدرسية:**
   - قنوات تواصل رسمي بين المعلم وولي الأمر لمتابعة مستوى الطالب الأكاديمي.
   - صندوق استفسارات وشكاوى أولياء الأمور مع الإدارة وتتبع دورة حياة الشكوى.

## 11. تجربة المستخدم والتجاوب (Responsive UI: Mobile & Desktop)

- **الهواتف الذكية (Mobile-First):** شريط تنقل سفلي (`Bottom Navigation Bar`) يضم الأزرار الخمسة الأساسية حسب الدور، وقوائم سحب جانبية (`Drawer`) للخيارات الموسعة.
- **الحواسيب والشاشات الكبيرة (Desktop):** شريط جانبي أيمن دائم (`RTL Sidebar`) مع إبراز مساحة العمل النشطة، وعرض النوافذ المتعددة (فيديو + سبورة + قارئ) جنباً إلى جنب.

## 12. حواجز الأمان وحماية الصلاحيات (Multi-Tier Security Boundaries)

1. **حاجز المستوى الثاني للأدوار (Two-Level Role Barrier):**
   - الخادم يرفض رفضاً قاطعاً برمز `403` أي محاولة لتعديل رتب الحسابات (`role`) من خلال مسارات المدرسة ما لم يكن الفاعل مطوراً أو مدير منصة.
   - مدير المدرسة (`manager`) لا يستطيع تصعيد نفسه أو غيره إلى مطور.
   - الواجهة لا تعرض أي خيار لتغيير رتب الحسابات.
2. **الأمان الافتراضي للوسائط:** الكاميرا والمايكروفون مغلقان دائماً عند الدخول ولا يبدآن إلا بنقرة صريحة وموافقة معتمدة من ولي الأمر.
3. **الأرشفة بدلاً من الحذف:** السجلات الأكاديمية والحسابات تعطل وتؤرشف مع توثيق الأسباب في `AuditLog`.

## 14. خطة البناء التتابعية المعتمدة (Phased Build Roadmap)

خطة تنفيذية منضبطة تبدأ من المرحلة 5 حتى المرحلة 11:

### المرحلة 5: بناء هيكل التطبيق الموحد، الثيم، والمخزن التفاعلي (Base Shell & State Store)
- إنشاء ملف المدخل الموحد `school.html` مع ربط الخطوط والمتغيرات السومرية.
- كتابة ملفات التنسيق الأساسية بدعم كامل لـ RTL والوضع الليلي/النهاري.
- بناء مخزن الحالة المركزي `sumer-state.js` (`SumerStore`).
- بناء موجه المسارات `sumer-router.js` (`SumerRouter`) مع حواجز الصلاحيات.
- بناء مصنع المكونات البصرية المشتركة `sumer-ui.js` (`SumerUI`).

### المرحلة 6: بوابة الزوار وتقديم الطلبات والتجربة المجانية (Public Gateway & Onboarding)
- تطوير شاشة بوابة الزوار `view-guest.js` (`#welcome`, `#guest`).
- ربط تسجيل الدخول الموحد بحسابات شنو منو (`#auth/login`).
- نموذج تسجيل الطالب وبدء الـ 30 يوماً التجريبية (`#auth/register-student`).
- نموذج تقديم طلب انضمام كمعلم بانتظار اعتماد الإدارة (`#auth/apply-teacher`).
- عرض كتالوج المناهج العراقية العامة للقراءة والاستكشاف.

### المرحلة 7: مساحة عمل الطالب والمناهج والقارئ الرقمي (Student Workspace & Curriculum)
- تطوير شاشة مساحة الطالب الشاملة `view-student.js` (`#student/*`).
- ربط جدول الطالب، الحصص القادمة، والواجبات المستحقة.
- تطوير عارض المناهج العراقي المزدوج `view-curriculum.js` و `sumer-reader-pane.js` (108 كتب و 17,232 صفحة OCR).
- دمج مكونات التقدم والحضور واستعراض كشف الدرجات للطالب.

### المرحلة 8: مساحة عمل المعلم وإدارة الحصص والدرجات (Teacher Workspace & Classes)
- تطوير شاشة مساحة المعلم `view-teacher.js` (`#teacher/*`).
- عرض الفصول والمواد المكلف بها المعلم، وقوائم الطلاب الحقيقيين.
- واجهة رصد الحضور التفاعلي، ورصد الدرجات والتقييمات المباشرة.
- واجهة إدارة الواجبات ومراجعة تسليمات الطلاب.

### المرحلة 9: مساحة عمل ولي الأمر المستقلة (Guardian Workspace)
- تطوير شاشة مساحة ولي الأمر المستقلة بالكامل `view-guardian.js` (`#guardian/*`).
- لوحة الأبناء والتبديل السلس للابن النشط.
- متابعة الحضور، الدرجات، والجداول لكل ابن.
- لوحة إدارة الموافقات السبع الصريحة وتحديثها اللحظي.
- صندوق الشكاوى والمقترحات ومتابعة ردود إدارة المدرسة.
- قنوات المراسلة المدرسية المنفصلة مع المعلمين والإدارة.

### المرحلة 10: مساحة عمل الإدارة المدرسية الموحدة (School Administration Workspace)
- تطوير شاشة الإدارة المدرسية الموحدة `view-admin.js` (`#admin/*`) التي تشمل الأقسام التسعة دون تشتيت.
- مراجعة واعتماد طلبات انضمام المعلمين الجديدة وتعيين المواد والصفوف.
- إدارة سجلات الطلاب وأرشفة الحسابات دون حذف إتلافي.
- إدارة ومتابعة صندوق الشكاوى والرد الرسمي عليها.
- واجهة استعراض سجل التدقيق الإداري الصارم (`AuditLog Viewer`).
- تأكيد وتثبيت حاجز منع التلاعب بالرتب (المستوى الثاني من الأمان).

### المرحلة 11: نواة الصف الموحد والسبورة والفحص الشامل (Classroom, Whiteboard & QA)
- تطوير شاشة الصف الموحد `view-classroom.js` (`#classroom/live/:code`, `#classroom/virtual/:code`).
- دمج مسرح البث المباشر WebRTC Star ومحرك المعلم الافتراضي (سارة، علي، مريم).
- تطوير السبورة التفاعلية `sumer-whiteboard.js` بدعم التكبير، التراجع/الإعادة، والشرائح، مع ربط زر **"إسقاط من المنهج"**.
- دمج ضوابط الخصوصية الصارمة (إغلاق الكاميرا والمايكروفون افتراضياً، ومنع التسجيل).
- إجراء اختبارات الجودة الشاملة لجميع المسارات، وفحص التجاوب عبر الأجهزة، وضمان اجتياز كافة اختبارات الـ Backend بنسبة 100%.

## 15. معايير الإنجاز الصارمة للوثيقة (Definition of Done)
- صدفة موحدة واضحة (`Unified Shell`) بمدخل مستقبلي واحد `school.html`.
- كافة مساحات العمل الأربعة المستقلة محددة بوضوح.
- مساحة ولي الأمر معزولة تماماً مع منع تصرفه كطالب في الصف.
- صلاحيات إدارة المنصة (`admin` / `developer`) مفصولة كلياً عن إدارة المدرسة (`manager`).
- المعلمون الافتراضيون الثلاثة مستخرجون حصراً من مصدر الحقيقة في الكود (سارة، علي، مريم).
- تدفق المناهج والقارئ والسبورة موثق بالبيانات الفعلية (108 كتب و 17,232 صفحة).
- منظومة الصف الموحد تضمن الخصوصية الصارمة والأمان الافتراضي.
- دورة حياة الواجبات والمهام موثقة من الإنشاء حتى رصد الدرجات.
- المنظومة المشتركة للحضور والتقدم والتقارير محددة لمنع تكرار المنطق.
- تحليل الفجوات البرمجية الشامل (`API Gap Analysis`) مصنف بدقة وفق الكود الفعلي (EXISTS, NEEDS EXTENSION, MISSING).
- خطة البناء التتابعية محددة ومفصلة من المرحلة 5 حتى المرحلة 11.
