## 1. فحص المشروع ونقطة الأمان

تم اعتماد آخر نسخة نظيفة مدمجة كأساس، وإنشاء أرشيف مستقل لها قبل نشر تغييرات المدرسة. لم تُحذف أي وظيفة قائمة.

### موجود ويعمل — يُحافظ عليه

- حسابات شنو منو الموحدة: التسجيل، التحقق، تسجيل الدخول، JWT وحماية المسارات.
- ملفات الطلاب وموافقات ولي الأمر.
- المواعيد والحصص وسجل التعلم والدرجات والتقارير.
- مكتبة المناهج العراقية، الفهرسة والملفات الموثقة.
- القارئ، الصف الدراسي، طبقة Canva، العمل دون اتصال والمزامنة.
- المعلم الافتراضي، الصوت وأذونات الكاميرا والميكروفون.

### موجود ويحتاج توسعة في المراحل التالية

- إدارة الكادر والحسابات التعليمية التفصيلية.
- ربط الطالب بحسابه المدرسي مباشرة بدل اقتصار بعض البيانات على ولي الأمر.
- صلاحيات دقيقة على مستوى كل عملية، لا على مستوى الواجهة فقط.
- إدارة الاشتراكات المدفوعة بعد انتهاء التجربة.

### غير داخل المراحل 1–4

- القبول الإداري الكامل، الأجور والاشتراكات بالمعلمين.
- الجداول الفردية والجماعية المتقدمة.
- الامتحانات والواجبات والنتائج النهائية.
- تطبيق Android وملفات APK/AAB والنشر على Oracle.

## 2. نظام التصميم

- الهوية المعتمدة: «مدرسة سومر الشاملة».
- الشعار: كتاب مفتوح + زقورة أور + شعاع المعرفة.
- اتجاه عربي RTL، وتخطيط متجاوب للهاتف والكمبيوتر.
- وضع نهاري وليلي محفوظ على الجهاز.
- مكونات مشتركة للرأس، التنقل، البطاقات، الحالات والاختصارات.

## 3. تسجيل الدخول

- بوابة مستقلة للمدرسة في `school-signin.html`.
- تستخدم `/api/auth/signin` نفسه ولا تنشئ حسابًا موازيًا.
- المستخدم الجديد ينتقل إلى تسجيل شنو منو، والحساب الحالي يدخل مباشرة.
- صفحات المدرسة غير المصرح بها تعيد المستخدم إلى بوابة المدرسة.
- تجربة 30 يومًا تبدأ عند أول تفعيل للوحة المدرسة، ولا تتجدد بإعادة الدخول.

## 4. الواجهة الرئيسية

- لوحة مدرسة متجاوبة تعرض بيانات المصدر الفعلية.
- تعرض اسم المستخدم، دوره المدرسي، حالة التجربة والأيام المتبقية.
- أدوار المدرسة: الإدارة، المعلم، الطالب، ولي الأمر والضيف.
- اختصارات مختلفة لكل دور مع الحفاظ على فصل دور المدرسة عن دور منصة شنو منو.

## معايير الإغلاق

- اختبارات صفحات المدرسة وعقد واجهة API ناجحة.
- اختبارات تجربة 30 يومًا ومنع إعادة منحها ناجحة.
- ملفات JavaScript تمر بفحص الصياغة.
- فحص تغييرات Git خالٍ من أخطاء المسافات والصياغة.
- المراحل 1–4 مكتملة كأساس تقني؛ الصلاحيات والبيانات التفصيلية لكل دور تُستكمل ضمن مراحل الإدارة والمعلمين والطلاب اللاحقة.

## قاعدة تنظيف الملفات بعد كل مرحلة

بعد نجاح كل مرحلة تُنفذ دورة تنظيف خاصة بها:

1. نجاح اختبارات المرحلة والاختبارات المشتركة المتأثرة.
2. حصر الملفات القديمة والمكررة المرتبطة بالمرحلة فقط.
3. التأكد بالبحث أن الملفات ليست مستوردة أو مرتبطة من HTML أو JavaScript أو الخادم أو الاختبارات أو عملية النشر.
4. توثيق البديل الذي حل محل كل ملف قديم.
5. حذف الملفات القديمة بعد ثبوت عمل البديل، ثم إعادة الاختبارات.
6. إبقاء نسخة الأمان خارج ملفات التشغيل وعدم نشر النسخ القديمة إلى Oracle.

لا يُحذف ملف مشترك أو أصل محفوظ أو ملف غير محسوم لمجرد أن اسمه قديم. الحذف يكون مستهدفًا وقابلًا للمراجعة بعد نجاح البديل.

## ملاحظة مجموعة الاختبارات القديمة

نجح 39 من 41 اختبار تكامل واسع. الاختباران المتبقيان انتهيا بمهلة انتظار داخل واجهتي Canva القديمة والحصة المباشرة، من دون فشل في قواعد البيانات أو الحسابات أو REST أو Socket.IO. اختبار Canva القديم ما زال ينتظر أسماء مؤشرات لم تعد تطابق عقد لوحة المدرسة الحالي، واختبار صفحة البث ينتظر تهيئة DOM قديمة. لم تُغيَّر الأصول الأصلية لهاتين الواجهتين ضمن المراحل 1–4، وتبقى إعادة مواءمة الاختبارين ضمن تنظيف الاختبارات القديمة قبل مرحلة النشر النهائية.
